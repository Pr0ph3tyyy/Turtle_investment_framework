## §17 数值引用契约（claim 绑定 · 强制）

**凡引用 §17 预计算数值，必须写成 claim 绑定 token，不得直接写数字：**

```
穿透回报率为 <claim id="cm17.11.aa2y.m3.gg" policy="round:2">2.89%</claim>，
目标买入价 <claim id="cm17.11.aa2y.m3.tbp">14.96</claim>。
```

- `id` 必须逐字取自数据包中 **「决策单元格（KV · 带 claim id）」** 块的 `claim:` 行，
  或 `{output_dir}/claims.json`。**不得自行编造 id。**
- 每个声明自带**校验策略**（`exact` / `round:2` / `alias` / `tolerance`），
  校验器按该策略机械比对；**对不上就是 unverified**。
- **裸数字默认不可信**：审计门槛（`report_consistency.py --gates --claims`）会列出
  所有未通过校验的 token，非空即失败（退出码 1）。

> 依据 [PCN](https://ar5iv.labs.arxiv.org/html/2509.06902)：数值保真是**呈现层**问题，
> 检索与引用都不足以保证；只有"机械绑定 + 失败即关闭"才能兜住误抄、错单位与编造。
> 校验为 **fail-closed** —— 未标记为通过的数字，一律视为不可信。

### 步骤3：安全边际与仓位

> **输入用悲观档**（§17.14 表A）：取 Agent B 选定 k 对应的 `GG_pess`，
> §17.11 的中性 `GG` 仅作对照。理由：文档要求穿透回报率使用最悲观参数
> （「不可能使用正常的利润，我们要打八折」`[42:45]`，「各种参数都是最低值」`[35:14]`）。
> Agent B 未给 k 时，按 ★ k=0.80 取行。

```
安全边际 JJ = GG_pess − II = [值] pct      ← 中性档 JJ 另列一行作对照

周期性修正（仅强周期，引用定性报告 维度三）：
  底部 → II − 1pct
  顶部 → II + 2pct
  非周期或中段 → 不调整

修正后安全边际 KK = [值] pct
```

> ⚠️ **仓位矩阵阈值不因悲观折扣而调整。** 折扣是**输入端**参数（改变 GG 的量级），
> 矩阵是**输出端**约定（把 KK 映射到仓位）。两者相互独立：
> 折扣的作用幅度约 `15% × GG`（实测 0.6–1.1 pct），只让贴着档位的标的下移一档 ——
> 这正是安全边际应有的作用，不是矩阵失效。详见 `known_issues.md` §3.21。

**仓位矩阵**：

| 条件 | 仓位建议 |
|------|---------|
| KK ≥ 1.5pct + 可信度高 + 陷阱低 | 标准仓位 |
| KK ≥ 1.5pct + 可信度高 + 陷阱中 | 70% |
| KK ≥ 1.5pct + 可信度中 + 陷阱低 | 70% |
| KK 0.5-1.5pct + 可信度高 + 陷阱低 | 50% |
| KK 0.5-1.5pct + 可信度中 + 陷阱低 | 观察（30%） |
| KK 0-0.5pct | 观察或等待 |
| KK < 0 | 不建仓 |
| 可信度低 | 观察或不建仓 |
| 陷阱高 + GG < II×1.5 | 排除 |

### 步骤5：绝对估值与基准价

> §17.8 预计算加速：若存在，直接引用。

估值指标：
- EV/EBITDA（< 8x → 偏低信号）
- 扣除现金PE（< 10x → 盈利能力强）
- FCF收益率（> 8% → 丰厚）
- 净负债/EBITDA（< 2x → 风险可控）
- 商誉/总资产（> 30% → 集中风险，仓位上限50%）

基准价与溢价（**估值读数，不是买点**）：
- ≤ 0% → "低于底价"（原措辞「买入就是胜利」）
- 0-30% → 安全边际充足
- 30-80% → 合理溢价
- \> 80% → 较高溢价

> ⚠️ **规则优先级（有约束力）**：**买点只能由步骤4 的悲观档目标买入价决定**
> （`target_buy_price_pess`）。本节「≤ 0%」只是**估值读数**，它与买点之间必须满足不变式
>
> ```
> 综合底价 ≤ 采纳档 k 的目标买入价      ⟺      {P ≤ 综合底价} ⊆ {P ≤ 买点}
> ```
>
> **基准价已按语义分组（2026-10-13）**：数据包 §17.8 现在给**两个**读数——
> **综合底价**（① 净流动资产/股、② 每股净资产、③ 10年最低价：回答"最差能值多少"）与
> **参考公允价**（④ 股息隐含价、⑤ 悲观FCF资本化：收益率型，回答"按某收益率要求值多少"）。
> **不得**把两者跨语义平均（旧口径的"综合基准价"正是这样一个既非底价也非公允价的数，
> 在 06862 上得到 9.44 > 买点 8.67，使"低于底价"读数在模型判定"不可买"的价位触发）。
> 「低于底价 — 买入就是胜利」**只能**基于**综合底价**；"安全边际/合理溢价"档位基于**参考公允价**。
>
> 否则框架会在它自己判定「不可买」的价格区间里发出"低于底价/买入就是胜利"信号——
> 实测 06862：综合基准价 9.34 > 悲观档（k=0.80）目标价 8.92，当前价 9.30 正落在该冲突区间。
> 违反时**不得**用文字解释掉（"保护不足"等），必须要么修正基准价构成（见下），要么
> 由 `scripts/check_report_fidelity.py` 报 I9 FAIL 并停手。
>
> **基准价构成要求**：① 每股量必须与 ③④ 同币种（报表币种 ≠ 交易币种时先折算）；
> ② 各锚点语义须一致——**不得**把「股息资本化价」（要求 3% 毛股息收益率的**公允价**）
> 与「清算/账面底价」等权平均，否则该均值既不是底价也不是公允价，且会系统性偏高。
> 若保留收益率类锚点，必须在表内分列口径并**禁止**用它单独触发"低于底价"读数。
