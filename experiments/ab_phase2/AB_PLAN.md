# 阶段 2 · A/B 实施方案：切片并行 vs 单上下文

> 目的：用预注册的量化指标决定**是否把「切片并行（v3）」转为 `/business-analysis` 默认模式**。
> 前置：阶段 0（5 个 skill）、阶段 1（`dimension_slicer.py`）、L1 契约（`dim_result.schema.json`）均已完成。
> 状态：**已设计，未执行 —— 按用户决定跳过（2026-10-13），v3 已直接落地为默认流程**。
> 本文保留为可执行的 runbook：若日后需要量化验证（例如换模型、扩样、或对结果有争议），
> 可直接按此执行；本文的 §9 威胁与局限即为**跳过 A/B 所承担的残余风险**。

## 0. 两个前置发现（直接决定方案形态）

### 发现 1：名义基线**不可运行** —— 必须定义代理臂

| 标的 | 年报正文 | +固定输入 | ≈token（0.6–1.0/字） | 128K 窗口 |
|---|---|---|---|---|
| 002984 森麒麟 | 201,678 | 245,005 | 147K–245K | ❌ |
| 00506 中国食品 | 410,807 | 454,134 | 272K–454K | ❌ |
| 02669 中海物业 | 533,182 | 576,509 | 346K–577K | ❌ |
| 06049 保利物业 | 422,695 | 466,022 | 280K–466K | ❌ |
| 06862 海底捞 | 573,252 | 616,579 | 370K–617K | ❌ |

**5/5 超窗**，即使按最乐观的 0.6 token/字 换算。因此「现行 1M 单 Agent」无法作为对照臂执行——这不是缺陷，而是**本次改造的动因本身**。

### 发现 2：没有 token 遥测 —— 上下文指标只能用**字符核算**

DSH 的会话存储（`~/.dsh/storages/**`）不含 `input_tokens` / `usage` 等字段（已实测：0 命中）。因此 M5 采用**确定性字符核算**（由冻结输入 + 切片 manifest 推导，**不依赖 agent 自报**），并同时给出 token 区间估计。

## 1. 三个臂的定义

| 臂 | 组成 | 材料 | LLM 调用 | 可运行 | 角色 |
|---|---|---|---|---|---|
| **A 名义基线** | 单 Agent，全部 6 维度 | 固定输入 + **年报全文** | 1 | ❌ 超窗 | 仅作**一次性可行性演示**（记录实测超窗量） |
| **A′ 材料对齐代理** | 单 Agent，全部 6 维度 | 固定输入 + **与 B 完全相同的 6 份切片** | 1 | ✅ | **主对照臂** |
| **B 切片并行（v3）** | 6 个维度子代理 + 1 个综合代理 | 共享前缀 + 各维度切片 → 6 份 JSON → 综合 | 7 | ✅ | 处理臂 |

**为什么以 A′ 为主对照**：A′ 与 B 的**材料逐字节相同**（同一份切片），唯一差别是「1 个上下文 vs 7 个上下文」——这才真正隔离了**架构变量**。若直接对比「全文单 Agent vs 切片并行」，则同时改变了上下文数量与材料范围两个变量，结论无法归因。

**A′ 同时是回退设计**：若 B 未通过验收，A′（单上下文 + 切片）本身就是可运行的降级模式。所以这次实验不存在"两条路都不可用"的风险。

## 2. 公平性控制（7 条，缺一不可）

| # | 控制 | 做法 |
|---|---|---|
| 1 | **冻结输入** | 把 `data_pack_market.md`、`computed_metrics.md`、年报 PDF/全文、6 份切片复制到 `experiments/ab_phase2/frozen/{code}/`，记录每份的 **sha256**；两臂只读该目录，禁止读 `output/` 下的历史产物 |
| 2 | **统一交付契约** | 两臂都产出**同一契约**的结构化结果：B 写 `dims/D1..D6.json`；A′ 写 `dims/all.json`（6 个契约对象的数组）。**契约与架构正交**，否则 M1 会退化成"输出格式严格度"的比较 |
| 3 | **统一审计** | 两臂跑**同一** `report_consistency.py --gates` 与**同一** numeric_audit 子代理 prompt |
| 4 | **隔离** | 每臂独立目录；A′ 的 prompt 明确禁止读 `armB/**`，B 的各维度 prompt 禁止读 `armA/**` 与其它维度的草稿；综合代理只读 6 份 JSON |
| 5 | **重复** | 每标的每臂 **2 次运行**（共 2×2×2 = 8 次）；报中位数与极差，不用单次结果下结论 |
| 6 | **顺序打散** | 8 次运行按固定随机种子打散（不按臂集中跑），摊平模型版本/负载漂移；记录每次的模型标识与起止时间 |
| 7 | **预注册** | 运行**之前**冻结 `preregistration.json`：假设、阈值、10 项事实清单**及其期望值**、运行计划。禁止事后改阈值或挑指标 |

## 3. 目录布局与运行流程

```
experiments/ab_phase2/
├── preregistration.json        # 运行前冻结（提交入库）
├── AB_PLAN.md                  # 本文
├── frozen/{code}/              # 冻结输入 + sha256 清单
├── runs/{code}/{arm}/run{N}/   # 每臂每次运行的产物
└── results.md                  # 结果表 + 决策

output/{code}_{company}/ab/     # 切片与中间产物（gitignored）
```

**单次运行（以 B 为例）**

```bash
CODE=002984.SZ; DIR=experiments/ab_phase2/frozen/002984
# 1) 切片（冻结前生成一次，两臂共用）
.venv/bin/python scripts/dimension_slicer.py --code $CODE \
    --output-dir experiments/ab_phase2/frozen/002984 --budget-chars 12000 --report-coverage
# 2) 6 个维度子代理（并行，各读共享前缀 + 自己的切片）→ dims/D*.json
# 3) 综合代理（只读 6 份 JSON）→ qualitative_report.md
# 4) 审计门（两臂同一命令）
.venv/bin/python scripts/report_consistency.py \
    --report <run_dir>/qualitative_report.md --output <run_dir>/consistency_report.md --gates
# 5) numeric_audit 子代理 → audit.md（末行 AUDIT_RESULT）
```

**A′ 运行**：单子代理，输入 = 共享前缀 + **全部 6 份切片拼接**，输出 = `qualitative_report.md` + `dims/all.json`。

**A（演示）**：单子代理，输入 = 固定输入 + 全文，记录**实际可载入字符数**与超窗量，随后终止（不产出报告）。仅跑 1 次，1 个标的。

## 4. 六项指标的精确测量

| # | 指标 | 公式 / 来源 | 性质 |
|---|---|---|---|
| **M1** | 结构化参数字段完整率 | 有值参数数 ÷ 应填参数数。**应填** = 40 个参数中，除 `holding_structure=false` 时的 `sotp_value_mm`/`sotp_discount_pct` 外全部；`null` 须伴随 `note` 否则计为缺失 | 确定性（`ab_metrics.py` 读 JSON） |
| **M2** | 跨段冲突数 + gates 退出码 | `report_consistency.py --gates` 输出中的「发现 **N** 处潜在冲突」+ exit code | 确定性 |
| **M3** | 审计 critical 数 | `audit.md` 中 severity=critical 的条数 + 末行 `AUDIT_RESULT` | 同一 prompt 的判定 |
| **M4** | 关键事实覆盖 | 见 §5：10 项（6 数值 + 4 定性）；**数值项必须"出现且正确"**才算覆盖 | 盲评 + 机械比对 |
| **M5** | 单上下文峰值输入 | 见下 | 确定性核算 |
| **M6** | 总耗时 | runner 记录的 start/end 时间戳，取中位数 | 确定性 |

**M5 的核算方式（不依赖自报）**

```
A′: peak = |固定参考文件| + Σ|6 份切片| + |指令|
B : peak = max over 6 dims (|共享前缀| + |该维度指令| + |该维度切片|) 与 综合调用(|6×JSON| + 指令)
```
其中固定参考文件、共享前缀、各切片长度均取自冻结目录与 `slice_manifest.json`（`used_chars`）。同时给出 token 区间（×0.6 / ×1.0）作为上界参考。

**验收阈值**：M5 ≤ **50,000 字符**（按 002984 实测 43–45K 加余量，约 128K 窗口的 39%）。
> ⚠️ **更正**：本文早期写的 26,000 字符是错的——核算共享前缀时漏计了 `data_pack_market.md`(17.0K)
> 与 `computed_metrics.md`(2.0K)，而这两项是硬数字唯一来源，必然出现在每个维度代理的输入里。
> 2026-10-13 的真实端到端运行实测为 43,236–45,377 字符（6 个维度），故据此修正阈值。

## 5. 关键事实清单的预注册程序（防事后挑选）

1. **独立提取**（运行前，fresh-context 子代理）：只读冻结的 `data_pack_market.md` + 年报 PDF，产出 **10 项**事实：**6 项数值 + 4 项定性**，每项给出 `item`、`expected_value`（数值项）、`acceptable_variants`、`source`（`DP§N` / `年报P.n`）。
2. **人工冻结**：我审阅后写入 `preregistration.json`。
3. **盲评**（运行后，fresh-context 子代理）：只读两臂报告（随机标为 X/Y）与清单，逐项返回 `{found, quoted_value, quote}`；**不知道哪份是哪臂**。
4. **机械判定**：`ab_metrics.py` 把 `quoted_value` 与 `expected_value` 归一化后比对（数值容差 1%）；定性项要求 quote 非空。

**示例项**（002984；正式值以预注册冻结为准，来源已标注）

| # | 类型 | 事实 | 期望值 | 来源 |
|---|---|---|---|---|
| 1 | 数值 | 2025 年营业收入 | 8,611.94 百万元 | DP§3 |
| 2 | 数值 | 5 年平均 ROE | 12.64% | CM§3 |
| 3 | 数值 | 2025 年货币资金 | 2,242.01 百万元 | DP§4 |
| 4 | 数值 | 2025 年应收账款 | 1,441.28 百万元 | DP§4 |
| 5 | 数值 | 2025 年分红支付率 | 32.23% | CM§4 |
| 6 | 数值 | 2025 年归母净利润同比 | −48.54% | CM§2 |
| 7 | 定性 | 护城河主要来自供给侧（规模制造成本） | — | 年报 P.15 起 |
| 8 | 定性 | 需求侧缺乏品牌溢价/转换成本 | — | MD&A |
| 9 | 定性 | 治理：审计意见为标准无保留 | — | DP§7 |
| 10 | 定性 | 主要原材料价格波动为主要风险 | — | 年报 风险提示 |

> 数值项占比 60% 是刻意的：把大部分评分交给**机械比对**，减少 LLM 评分的主观性。

## 6. 盲评协议（防污染）

- 评估子代理**全新上下文**，只接收：两份报告（随机标 X/Y）+ 预注册清单。
- **不告知**臂名、架构差异、切片信息。
- 每标的的 X/Y 映射由固定随机种子决定并记录在 `results.md`（评分完成后才公开）。
- 同一标的两次运行的报告**分别评分**（4 份报告 → 2 次盲评），避免跨 run 互相提示。
- 评分者必须给出**原句引用**；无引用一律记 `found=false`。

## 7. 决策规则

**通过条件（B 相对 A′）**

| 指标 | 通过线 |
|---|---|
| M1 字段完整率 | ≥ A′（允许差 1 个参数） |
| M2 冲突数 | ≤ A′，且 gates exit = 0 |
| M3 critical 数 | = 0，且 ≤ A′ |
| M4 事实覆盖 | ≥ 9/10 |
| M5 单上下文峰值 | ≤ 50,000 字符 |
| M6 总耗时 | ≤ 1.5 × A′ |

**判定细则**

- **任一指标落在运行间极差之内**（即单次差异小于同臂两次运行的自然波动）→ 该标的**加跑 2 次/臂**再判定。
- **M4 未达标 → 三分法定位**（这是最有价值的诊断）：
  1. 缺失事实的**来源页不在** `provided_pages` → **切片器问题**（改选页策略/预算）
  2. 来源页在切片内、且该事实**存在于某份 dim JSON**，但报告里没有 → **综合代理问题**
  3. 来源页在切片内，但 dim JSON 里也没有 → **维度子代理问题**（prompt/契约）
- **M1/M2/M3 未达标** → 属契约或闸门问题，与架构无关，先修契约再谈架构。
- **全部通过** → 阶段 3：切片模式转默认，并清除 1M 措辞（2.3）。
- **未通过** → 保持开关关闭，回退到 **A′**（单上下文 + 切片，可运行的降级模式），并把 M4 的定位结论写回包 2 方案。

## 8. 成本核算（无遥测下的可比口径）

| 口径 | A′ | B |
|---|---|---|
| LLM 调用数 | 1 | 7 |
| 总输入字符 | ≈ 固定 24.3K + 切片 Σ(69,785) + 指令 ≈ **96K** | 6×(10.8K+切片) + 综合 ≈ **164K** |
| **单上下文峰值** | **96,085 字符** ❌ | **43,236–45,377 字符** ✅（实测） |
| KV cache 收益 | 无（单次） | **共享前缀 6 次逐字节相同 → 命中** |
| 错峰 | — | 批量运行排错峰（官方 5 折） |

> 上表为 **002984 实测/核算值**。共享前缀应为 27,812 字符（含 data pack 与 CM）→ A′ ≈ 27,812 + 69,785 + 指令 ≈ 99.6K。
> B 的单维度峰值 = 27,812 + 维度指令(449–2,407) + 契约片段(435–1,797) + 切片(11.4–11.9K) = **43.2–45.4K 字符**。
> 注意 A′ 本身**不满足** M5 阈值——它是"当前唯一可运行的单上下文变体"，而不是候选方案；这正是本次改造的动因。

**结论**：B 的总输入约为 A′ 的 1.7×，但**峰值上下文降至 1/4**，且共享前缀可吃缓存。真正的判据是 M5（这是本次改造的核心动因），成本差异需结合你的实际单价评估。

## 9. 威胁与局限（诚实边界）

| 威胁 | 影响 | 缓解 |
|---|---|---|
| 仅 2 个标的（1 A股 + 1 港股，均制造/消费类） | 不能外推为普遍结论 | 结论限定为"这两个标的上"，推广前需扩样 |
| 每臂 2 次运行 | 只能给极差，不能给置信区间 | 明确写"极差"而非"标准差"；borderline 加跑 |
| 无 token 遥测 | M5 是字符上界估计 | 同时给 token 区间；若 GUI 显示实际用量则回填校准 |
| 模型版本漂移 | 跨 run 不可比 | 记录模型标识与时间戳；运行顺序打散 |
| 评分者同族模型 | 可能自我偏好 | 盲评 + 数值项机械比对 + 强制引用 |
| **名义基线不可复现** | 无法声称"优于 1M 单 Agent 本身" | 明确限定：只声称"优于当前唯一可运行的单上下文变体 A′" |
